Analyze the provided logs for a multi-stage attack. This offense triggers when Initial Compromise events (e.g., Malware, Exploit) are followed by Post-Compromise Activity (e.g., AD group changes, Botnet C2, reconnaissance) within 1 hour on the same IP.

**FIRST CHECK — benign correlations that MUST be scored 0.0-0.3 (Verdict: 'Contained_False_Correlation') even when the rule "successful compromise + post-activity" pattern looks met.** These are recurring false positives where an infrastructure host doing its normal job trips a composite rule. If ANY of the following clearly describes the evidence, stop and score it low:

1. **Network-monitoring / SNMP polling host.** Repeated outbound connections whose destination port is 161 (SNMP), 6556 (check_mk), or other monitoring ports, especially from a host named like a monitoring server (librenms, zabbix, nagios, prtg, observium). This is polling of monitored devices, NOT C2 "beaconing to uncategorized IPs".
2. **Domain Controller doing DC work.** Events dominated by "the domain controller validated the credentials for an account" for many different normal users, plus service-account logons (e.g. palo.alto, nextcloud, backup) and "Application of Group Policy". This is normal DC operation. A DC is also a DNS resolver, so any DGA / botnet / "Potential DNS Vulnerability" flag on a DC or DNS server is forwarded client DNS, NOT the DC being infected. Do NOT call this a "compromised domain controller".
3. **Windows servicing / .NET compilation artifacts mislabelled as exploits.** A "MOVEit Transfer Vulnerability Exploit Filename" (or similar filename-regex exploit rule) that resolves to a `*.cmdline` / `*.0.cs` file under `C:\Windows\Temp\<random>\` created by powershell.exe or csc.exe is the standard .NET / `Add-Type` compilation artifact — benign. `DismHost.exe`, `TiWorker.exe`, `TrustedInstaller.exe` and similar Microsoft-signed servicing processes running from `C:\Windows\Temp\<GUID>\` are benign Windows servicing, not "process launched from temp by an attacker".
4. **SYSTEM property-touch on a local account, without real escalation.** "A user account was changed" (4738) or "A security-enabled local group was changed" (4735) performed by the machine account / NT AUTHORITY\SYSTEM (Logon ID 0x3E7) is a LAPS / GPO / imaging property refresh. Treat it as escalation ONLY if it is accompanied by an actual member-add (4732 / 4728 / 4756), account creation (4720), or password reset (4724) tied to a *preceding interactive or network logon by a non-SYSTEM principal*. Absent those, it is benign administration.
5. **Security appliance emitting self-alerts.** A host that is itself an IPS/monitoring manager (e.g. McAfee/Trellix Network Security Platform Manager, generic "Network Security Platform Alert" volume, WinCollect collector) generating generic platform alerts plus logons to its own admin console is the appliance doing its job.

Apply these specific heuristics to map your findings to the scoring rubric:
1. Map to 0.0 - 0.3 (CLEAR FALSE POSITIVE) if any FIRST CHECK item matches, OR if the Initial Compromise events show a 'Security_Action' of 'Blocked', 'Cleaned', or 'Dropped' (the AV/Firewall stopped the threat), AND the subsequent Post-Compromise events appear to be unrelated, benign administrative tasks or routine traffic. Verdict: 'Contained_False_Correlation'.
2. Map to 0.4 - 0.6 (SUSPICIOUS BUT INCONCLUSIVE) if the Initial Compromise was logged but the 'Security_Action' is unknown or 'Allowed', yet the Post-Compromise activity is ambiguous (e.g., generic scanning). Verdict: 'Suspicious_Investigation_Needed'.
3. Map to 0.9 - 1.0 (CONFIRMED COMPROMISE) only if NO FIRST CHECK item applies AND the Initial Compromise events were 'Allowed' or successful, AND they are clearly followed by highly malicious Post-Compromise actions from the same host — for AD this means an actual privileged-group MEMBER ADD (4732/4728/4756), account creation, or password reset tied to a non-SYSTEM logon; for network this means a genuine C2 channel, not monitoring/SNMP polling. Verdict: 'Active_Multi_Stage_Compromise'.
