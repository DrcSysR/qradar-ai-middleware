CRITICAL REMINDER: This SIEM rule detects Brute Force or Password Spraying attempts (at least 10 authentication failures for the same Username in 5 minutes). Your task is to determine if this is a benign user error (e.g., forgotten password, stale cached credentials on a mobile device) or a genuine malicious attack.

FIRST CHECK — BENIGN USER ERROR (OVERRIDES every band below; score 0.1-0.2, verdict 'Benign_User_Error_or_Cached_Credentials'). Before you even consider "compromise", look at WHERE the SUCCESSFUL login came from relative to the failures:
- If the success came from the SAME Source_IP(s) as the failures, AND those IP(s) are EITHER (a) internal / RFC1918, OR (b) a residential/mobile ISP consistent with a remote employee — especially Ukrainian consumer ISPs (Kyivstar 46.211.x / 5.248.x / 94.153.x, Lifecell/Vodafone-UA 31.144.x, Ukrtelecom & other UA 178.136.x / 178.137.x / 194.44.x / 188.163.x) — then this is the EMPLOYEE THEMSELVES (wrong password / stale cached credentials on a phone or mapped drive), NOT an attacker. Score 0.1-0.2.
- A 'fail-then-success' pattern where the success is from the user's OWN IP is the SINGLE MOST COMMON FALSE POSITIVE for this rule. It is NOT a 'Successful_Brute_Force_Compromise'. Do not be fooled by the mere presence of a success.
- Many DISTINCT external IPs each with only 1-2 successes for the SAME user, all from one country's mobile/residential ranges, is a remote worker on a rotating dynamic IP — benign, NOT a distributed compromise.
- Only escalate to compromise (band 4) when the success comes from a clearly HOSTILE source: an IP that is part of the failing-attack burst AND is external/unrecognized AND inconsistent with this user's normal remote-access pattern.

Analyze the provided authentication logs. Pay close attention to the 'Target_User', 'Source_IP', 'Failed_Attempts', and especially the number of 'Unique_Source_IPs'. Apply the following heuristics to map your findings to the scoring rubric:
1. Map to 0.0 - 0.3 (CLEAR FALSE POSITIVE) if all failed attempts originate from a SINGLE, recognized internal 'Source_IP' (e.g., a known user workstation or mobile device IP range), and the total 'Failed_Attempts' is moderate (e.g., 10-30). This strongly indicates a user typing the wrong password manually, or a device continuously trying to authenticate with expired cached credentials (e.g., email client or mapped drive). Verdict: 'Benign_User_Error_or_Cached_Credentials'.
2. Map to 0.4 - 0.6 (SUSPICIOUS BUT INCONCLUSIVE) if the failed attempts originate from a single UNKNOWN or external 'Source_IP' (e.g., via VPN or external gateway), OR if the 'Failed_Attempts' count is excessively high (e.g., hundreds of attempts from one IP) but all are unsuccessful. This is a suspicious targeted brute force attempt, but without evidence of a successful login, the immediate impact is low. Verdict: 'Targeted_Brute_Force_Unsuccessful'.
3. Map to 0.7 - 0.8 (HIGHLY SUSPICIOUS) if the failed attempts for the single user originate from MULTIPLE distinct 'Source_IP's (Unique_Source_IPs >= 3), especially if they are external or unrecognized. This indicates a distributed brute force or password spraying attack targeting this specific account. Verdict: 'Distributed_Brute_Force_Attack'.
4. Map to 0.9 - 1.0 (CONFIRMED COMPROMISE) if, IN ADDITION to the failed attempts, there is a subsequent SUCCESSFUL authentication (Logon Type 2, 3, or 10) for the 'Target_User' from one of the attacking 'Source_IP's — AND that Source_IP passes the FIRST CHECK as a clearly HOSTILE source (external/unrecognized, not internal, not a residential/mobile ISP matching the employee's normal remote access). This critical pattern means the brute force attack succeeded and the account is compromised. Verdict: 'Successful_Brute_Force_Compromise'. If the success is from the user's own internal/known-ISP IP, this is the FIRST CHECK false positive, NOT a compromise.

Output ONLY a JSON object with keys 'score' (float 0.0-1.0), 'verdict' (one of the strings above), 'explanation' (≤15 words, single sentence naming the user and the decisive source-IP signal).
