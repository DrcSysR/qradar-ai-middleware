CRITICAL REMINDER: This offense triggers when a local device ('Source_IP') generates traffic matching a banned/rogue software application (e.g., Yandex, Kaspersky, VKontakte, Mail.ru, Dr.Web). The SIEM rule groups the offense and applies a temporary block based on this 'Source_IP'.
Your task is to hypothetically determine the state of the device at the 'Source_IP' based on its network traffic profile. You must differentiate between accidental web noise (e.g., the user visited a legitimate site that loaded a banned tracking pixel) and the actual presence of rogue software installed on the device.
Analyze the AQL logs, focusing on the 'Source_IP', the 'App' name, 'Event_Count', and data volume ('Total_Bytes_Sent'/'Received'). Apply these heuristics to map to the scoring rubric:
1. Map to 0.0 - 0.3 (CLEAR FALSE POSITIVE) if the 'Source_IP' generates very few events (Event_Count is 1-5) with minimal data transferred (Kilobytes), and the 'App' is a generic web service ('yandex', 'vkontakte'). This indicates the device merely loaded a background tracker or ad banner in a web browser. Verdict: 'Benign_Web_Noise_No_Installation'.
2. Map to 0.4 - 0.6 (SUSPICIOUS BUT INCONCLUSIVE) if the 'Source_IP' generates moderate to high Event_Counts and Megabytes of transferred data to a web service 'App'. This indicates the user at this device is actively browsing a banned website (policy violation), but there is no definitive proof of a dedicated rogue agent installed. Verdict: 'Policy_Violation_Active_Browsing'.
3. Map to 0.9 - 1.0 (CONFIRMED COMPROMISE) if the 'App' explicitly indicates a dedicated software agent or updater (e.g., 'kaspersky', 'drweb-update', 'mail.ru-agent', 'yandex-disk'), OR if the 'Source_IP' exhibits continuous, periodic beaconing (high Event_Count) with significant data transfer to these banned services. This strongly indicates the hypothetical presence of actively running rogue software physically installed on the user's device. Verdict: 'Active_Rogue_Software_Installed'.
