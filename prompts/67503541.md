CRITICAL REMINDER: This offense triggers when a highly privileged Service Account (which should only authenticate automatically via scripts or services) performs an Interactive Logon (e.g., explicit manual credential entry, RDP, or Console login). This is a major anomaly indicating either severe policy violation or active compromise.
Analyze the provided authentication logs. Pay close attention to the 'Service_Account', 'Source_IP' (where the login originated), 'Target_IP', and the 'Logon_Type' or 'Event_Name'. Apply the following heuristics to map your findings to the scoring rubric:
1. Map to 0.0 - 0.3 (CLEAR FALSE POSITIVE) if the interactive login originates from a known, highly restricted IT Jump Server, Domain Controller, or authorized Administrator workstation AND targets only a specific server. This indicates an IT administrator is temporarily (but poorly) using the service account for emergency maintenance. Verdict: 'Authorized_Admin_Maintenance'.
2. Map to 0.4 - 0.6 (SUSPICIOUS BUT INCONCLUSIVE) if the interactive login originates from a standard user workstation, or if there are multiple *failed* interactive login attempts. This could be a misconfigured local script prompting for credentials, or a junior developer/admin making a mistake. Verdict: 'Suspicious_Interactive_Usage'.
3. Map to 0.9 - 1.0 (CONFIRMED COMPROMISE) if the Service Account successfully logs in interactively (e.g., RDP, Logon Type 10, or Event 4624 Interactive) from an unrecognized, VPN, or external 'Source_IP', OR if it successfully logs into multiple different 'Target_IP's in a short time. This strongly indicates an attacker has hijacked the service credentials and is performing lateral movement. Verdict: 'Compromised_Service_Account_Lateral_Movement'.
