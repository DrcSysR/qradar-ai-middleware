CRITICAL REMINDER: This SIEM rule tracks administrative logins to detect unauthorized Lateral Movement while filtering out legitimate IT operations. 
Context specific to this environment:
- Domain Admins legitimately use 'Run As' or interactive logins to perform tasks on specific user devices.
- The local 'admin' account is frequently provided to users for temporary 'Run As' elevation on their own devices (often using unique/LAPS passwords). Therefore, multiple 'Run As' events across the network by 'admin' are expected. HOWEVER, a FULL interactive desktop login (Logon Type 2 or 10) by the local 'admin' account is an anomaly.
Analyze the provided logs, focusing on 'Admin_Account', 'Logon_Type', 'Event_Name', and critically, the 'Unique_Targets_Count'. Apply these heuristics to map to the scoring rubric:
1. Map to 0.0 - 0.3 (CLEAR FALSE POSITIVE) if a Domain Admin logs into a very small number of devices (Unique_Targets_Count is 1 or 2) for targeted support, OR if the local 'admin' account triggers 'Run As' / elevation events (not full interactive desktop logins) regardless of the number of targets. Verdict: 'Legitimate_Admin_Task_or_RunAs'.
2. Map to 0.4 - 0.6 (SUSPICIOUS BUT INCONCLUSIVE) if the local 'admin' account performs a FULL interactive login (Logon Type 2 - Console or Logon Type 10 - RDP) on a user workstation. This indicates a user is fully logging into the local admin profile rather than just elevating a process, which is a policy violation but might not be an external attack. Verdict: 'Policy_Violation_Full_Local_Admin_Login'.
3. Map to 0.9 - 1.0 (CONFIRMED COMPROMISE) if ANY admin account (Domain Admin or local 'admin') sequentially authenticates to multiple different devices in a short period (Unique_Targets_Count >= 3) using full interactive or network logons. This is a critical indicator of credential theft and active Lateral Movement across the network. Verdict: 'Active_Lateral_Movement_Detected'.
