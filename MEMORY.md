# 🧠 QRadar AI Middleware — Файл пам'яті (Memory & Context)

Цей файл є єдиним джерелом знань (Source of Truth) для AI-асистентів (Gemini CLI, Claude Code), що працюють з цим репозиторієм. Він описує архітектуру, логіку роботи, правила розробки та деплою проєкту.

---

## 📌 Загальний огляд проєкту
**QRadar AI Middleware** — це інтеграційне рішення, розроблене для автоматизації тріажу (SOC Tier-1/2) та первинного аналізу інцидентів (Offenses) в **IBM QRadar SIEM**. Middleware використовує штучний інтелект (локальний **Ollama з Qwen** або **Google Vertex AI з Gemini**) для глибокого аналізу сирих подій (AQL logs) та винесення вердикту. Це дозволяє суттєво зменшити Alert Fatigue (втому від сповіщень) та автоматично закривати False Positives.

---

## 🏗️ Архітектурні компоненти

Проєкт складається з кількох ключових служб та періодичних завдань:

### 1. Головний сервіс: `app.py` (FastAPI)
*   **Порт:** Працює на порті `5000` (під керуванням gunicorn/uvicorn як системна служба `qradar-middleware`).
*   **Ендпоінт `/universal-analysis` (POST):** Приймає `offense_id` та параметр `is_manual` (чи запущено ручний аналіз через Web UI).
*   **Логіка обробки інциденту:**
    1.  Перевіряє статус інциденту в SQLite БД (`ai_state.db`), щоб уникнути повторного аналізу або гонки процесів (`PROCESSING` / `PROCESSED`).
    2.  Робить запит до QRadar API для отримання деталей офенсу (тип, джерело, назва, час запуску).
    3.  Через `prompts_loader.py` резолвить відповідний аналітичний промпт (`.md` файл у `/prompts`) та файл запиту (`.aql` у `/queries`) на основі substring-матчингу назви офенсу з конфігом `prompts.json`.
    4.  Формує та виконує точковий AQL-запит у QRadar Ariel для отримання сирих подій за часовим вікном інциденту (з буфером).
    5.  Збирає внутрішній контекст інфраструктурних активів (Asset Context), перевіряючи залучені IP-адреси за кешованими Reference Sets (ролі серверів: Web, Active Directory, Database тощо).
    6.  Надсилає зібраний промпт (інструкція + контекст активів + сирі логи) до обраного AI провайдера (Ollama або Vertex AI).
    7.  Парсить JSON-відповідь AI (ключі: `score`, `verdict`, `explanation`).
    8.  Якщо вердикт низький (`score` ≤ 0.6) та режим автоматичний (`is_manual=False`), автоматично закриває інцидент у QRadar із кодом причини `1`.
    9.  Якщо вердикт високий (`score` > 0.6), перепризначає інцидент на аналітика (вказаного у `prompts.json`).
    10. Записує результат у QRadar у вигляді примітки (`Note`) та оновлює статус у SQLite як `PROCESSED`.
*   **Web UI (`/`):** Містить простий, але стильний кастомний інтерфейс для ручного тригеру аналізу за номером інциденту.

### 2. Періодичний поллер: `poller.py`
*   Запускається регулярно (наприклад, через systemd timer чи cron).
*   Отримує з QRadar список усіх **OPEN** інцидентів за останні 24 години (`LOOKBACK_TIME_MS = 24h`).
*   Фільтрує їх за правилами, що налаштовані в `prompts.json`.
*   Для нових інцидентів, які ще не мають нотатки AI та статусу `PROCESSED` у базі даних, надсилає запит на `/universal-analysis`.
*   Має механізм блокування подвійного запуску (`poller.lock`) та захист від відмови сервісу (зупиняє цикл при кількох Connection Error поспіль).

### 3. Мисливець на ботнети: `botnet_scan.py`
Працює у дві фази:
1.  **REVIEW (Очищення):** Перевіряє записи в Reference Set `ME-PA-Suspicious-IP-Addresses`. Якщо IP не фіксувався активним понад 48 годин (`review_stale_hours = 48`), видаляє його з чорного списку (розблокування).
2.  **HUNT (Полювання):** Виконує складний AQL-запит за останні 7 днів для пошуку повільних ротаційних ботнетів (Slow-rotation Bruteforce), які намагаються обійти стандартні ліміти QRadar (Failed Logins від 5 до 30, успішних входів 0, унікальних користувачів ≥ 2). Кандидатів додає до Reference Set `ME-PA-Suspicious-IP-Addresses`.

### 4. Звітність антивірусу: `falcon_pua_scan.py`
*   Щоденний звіт по CrowdStrike Falcon PUP (Potentially Unwanted Programs) та ML-детекціях.
*   Вилучає відомі хибні спрацьовування (FP) через налаштовані regex-патерни шляхів та SHA256-дозволені списки.
*   Дедуплікує детекції по парі `(sha256, hostname)` у таблиці `falcon_pua_reported` в базі `ai_state.db`.
*   Надсилає гарно форматовані зведені алерти в Google Chat через webhook.

### 5. Спільний завантажувач: `prompts_loader.py`
*   Забезпечує парсинг `prompts.json` та пошук збігів назв інцидентів QRadar.
*   Дозволяє задавати метадані, аналітиків, файли запитів та Reference Sets для очищення.

## 🗄️ Бази даних та Стан (State Management)
Локальний стан зберігається у SQLite: `/opt/qradar-middleware/ai_state.db`
*   Режим `journal_mode=WAL` та `synchronous=NORMAL` дозволяють паралельні швидкі читання та стабільність при збоях живлення.
*   **Таблиці:**
    *   `offenses` — історія обробки інцидентів (`offense_id`, `status` (`PROCESSING`, `PROCESSED`, `NO_EVENTS`, `AI_ERROR`), `score`, `verdict`, `last_updated`).
    *   `botnet_scan` — історія блокувань та розблокувань IP-адрес ботнетів.
    *   `falcon_pua_reported` — реєстр уже надісланих у чат подій CrowdStrike для уникнення дублювання.

## ⚙️ Конфігурація та Секрети

### 1. `/opt/qradar-middleware/config.json` *(GITIGNORED)*
Містить критичні налаштування та секрети:
*   `qradar_url` та `qradar_token` (Sec Token).
*   `ollama_url`, `fast_model` (`qwen2.5-coder:7b`), `deep_model` (`qwen2.5-coder:32b`).
*   `ai_provider` (`ollama` або `vertex`) та `ai_fallback` (на випадок збою основного).
*   `vertex_project`, `vertex_location`, `vertex_fast` (`gemini-1.5-flash`), `vertex_deep` (`gemini-1.5-pro`).
*   `reference_sets` — перелік наборів для побудови внутрішнього контексту.
*   Параметри для `botnet_scan` та `falcon_pua_scan` (включаючи `google_chat_webhook`).
*   `botnet_dry_run` — якщо `true`, блокування та видалення з Reference Set лише логуються.

### 2. `prompts.json` *(Коммітиться)*
Мапінг правил. Формат запису:
`"Substring назви інциденту": [ "PromptFile.md", "AssigneeUsername", "QueryFile.aql", "RefsetCleanupOnFP" ]`
*   При FP-вердикті (`score` ≤ 0.6) IP автоматично видаляється з вказаного `RefsetCleanupOnFP`.

## 🔄 Деплоймент та Автооновлення (`autoupdate.sh`)
У проєкті реалізовано повністю автоматизований Git-based CD:
1.  Будь-який пуш або злиття в гілку `main` на GitHub є релізом.
2.  На сервері працює періодичний крон, який викликає `/opt/qradar-middleware/autoupdate.sh`.
3.  Скрипт робить `git fetch`, порівнює локальний SHA з віддаленим.
4.  При виявленні змін виконується `git pull --ff-only`.
5.  Служба перезапускається: `systemctl restart qradar-middleware`.
6.  Протягом 30 секунд виконується Health-check опитування локального веб-сервісу.
7.  Якщо сервіс лежить, скрипт автоматично робить **rollback** (`git reset --hard PREV_SHA`), перезапускає службу і відновлює робочий стан.

## 🛡️ Правила розробки для AI-асистентів (Rules of Engagement)

> [!IMPORTANT]
> **Повноваження AI (AI Permissions):**
> *   AI-асистент має повне право самостійно виконувати будь-які файлові операції (створення, модифікація, видалення коду, промптів чи конфігів) у межах проєкту для вирішення поставлених задач.
> *   Дозволено вільно використовувати Git (`git add`, `git commit`, `git push origin <branch>`) для синхронізації змін без додаткових запитів чи підтверджень від користувача.
> *   **Обов'язкова демонстрація змін перед коммітом (Pre-commit Diff Preview):** Перед кожним коммітом ШІ-асистент зобов'язаний продемонструвати користувачеві плановані зміни у вигляді кольорового `diff`-блоку (видалення ` - ` підсвічуються червоним, додавання ` + ` — зеленим), щоб користувач міг провести швидкий код-рев'ю перед збереженням.
> *   Кожен пуш у гілку `main` є автоматичним релізом у прод-сервіс (через `autoupdate.sh`), тому перед коммітом/пушем у `main` необхідно обов'язково валідувати коректність коду.

> [!IMPORTANT]
> **Принципи кібербезпеки (Security First):**
> *   Ніколи не додавати паролі, токени чи сертифікати в код.
> *   Усі конфігураційні `.json` файли (крім `prompts.json`) знаходяться в `.gitignore`. Дотримуватись цього суворо!
> *   Усі запити до зовнішніх API (Google Vertex AI тощо) повинні виконуватись із увімкненою валідацією SSL (`verify=True`). Для локального QRadar API, що використовує self-signed сертифікати, допустимо `verify=False`.

> [!TIP]
> **Збереження структури:**
> *   Зберігайте оригінальні коментарі та docstrings у коді, якщо вони не стосуються ваших змін безпосередньо.
> *   Код написаний чистою мовою Python (FastAPI/asyncio) та Shell-скриптами. Дотримуйтесь асинхронності в `app.py`.
