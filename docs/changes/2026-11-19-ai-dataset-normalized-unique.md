# 2026-11-19 — Датасет: нормалізована схема + лічильник унікальності

Продовження [thread-injection-prefilter-and-ai-dataset](2026-11-19-thread-injection-prefilter-and-ai-dataset.md). Замість «кожен розбір з повним промптом» (≈6 КБ стиснутого на запис, 92% — те саме правило) журнал веде **унікальні випадки**.

## Схема (`ai_dataset.db`, `ai_dataset.py`)
- `ai_unique` — один рядок на унікальний випадок: `ukey = sha1(нормалізований підпис)`, `source` (`qradar`|`cortex`), `lens`, `n_seen`, `n_events`, `n_hosts` + `hosts_json` (≤50), `first_seen/last_seen`, `signature_json`, один приклад промпту (`example_prompt_z`, zlib, лише для першого входження), `t1_*`, `final_*`, `vertex_verdict/score/ts` (заповнюються окремо, суддя Vertex — ще не реалізовано), `human_label`.
- `ai_log` — легкий журнал кожного розбору (без промпту), кільцевий буфер `ai_dataset_max_rows` (300000). Стара таблиця `ai_dataset` (3 пробні рядки з попереднього коміту) залишається невикористаною.
- Нормалізація (`norm_value`): регістр, `\Users\<хтось>\` → `<u>`, GUID/hex ≥12 → маски, IPv4 → `<ip-int>`/`<ip-ext>`, числа → `#`. Із підпису виключено хост, користувача, час, лічильники, SHA256, локальний IP.
- Радар: підпис = лінза + множина нормалізованих рядків подій AQL (≤30). Cortex: підпис = множина нормалізованих полів алертів (`CORTEX_SIG_FIELDS`); запис робить `cortex_incident_ai.analyze` після свіжого вердикту Vertex.
- Права: після запису `chmod 666` на БД/-wal/-shm — і сервіс (qmiddleware), і таймери (root) пишуть в один файл; інакше root-створений `-wal` давав сервісу «readonly database» (так і сталося на першому деплої, коли файл створила моя ручна перевірка під root).

## Не зроблено
Суддя Vertex для унікальних випадків, ручна розмітка контрольного набору (150–200), `human_label` (повторне відкриття офенсу), навчання.
