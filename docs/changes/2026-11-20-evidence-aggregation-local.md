# Агрегація доказів перед підрізанням для tier-1 (llm01) — прапорець вимкнено

## Проблема
Для провайдера `openai` (llm01, ctx 8192) `build_prompt` віддавав `str(events)[:max_chars]`, де `max_chars = max(500, …)`. Для «важких» інструкцій це 500 символів — 1–3 сирих рядки; решта втрачалась мовчки (знайдено при розмітці датасету 19–20.11).

## Зміна
- `evidence_agg.py`: стадія 1 — злиття однакових рядків (час і сирий payload не входять у ключ групи, лічильники `Events` складаються); стадія 2 — якщо не влазить, згортається поле з найбільшою кількістю різних значень (`destinationip` → `<n> distinct (зразки…)`); стадія 3 — рядки, що все одно не влізли, відсікаються цілими, в кінець додається маркер `_omitted` (скільки груп і подій пропущено).
- Формат виходу — той самий Python-літерал списку словників, тож розбір збережених промптів (`tools/dataset_label.py`) працює без змін.
- Вмикається `local_evidence_aggregate` (config_schema, типово `false`), лише для `openai`. Датасетний підпис (`ai_dataset.signature_qradar`) рахується з сирих подій і не змінюється.
- Smoke-тест `check_evidence_agg`.

## Офлайн-перевірка (реальні дані)
Офенс 2174916 («Excessive Firewall Denies Across Multiple Hosts»): 1400 сирих рядків, 1.9 МБ. Було: перші 500 символів = 1–3 рядки CRE/PA. Стало: ≈2.4 КБ — 4 групи з лічильниками (1156 подій UDP/443 на 198 різних призначень, 134 — DNS до шлюзу, 15 — DHCP, 87 — ICMP). Решта перевірених офенсів (thread injection, ransomware) вже агрегована в AQL і малого розміру — виграшу немає.

## Не зроблено / ризики
- Прапорець вимкнено: змінює вхід моделі, тож вердикти tier-1 зсунуться; перед вмиканням потрібен A/B на збережених випадках.
- Сирий payload у групі підрізається до 160 символів і для PA-рядків це лише заголовок syslog (без користі) — кандидат на другий крок («скорочення»).
- Скорочення довгих інструкцій use-case — окремий крок після агрегації.

## A/B на збережених випадках (2026-11-20, `tools/evidence_agg_ab.py`)
40 кандидатів (обрізані логи, офенси ≥2185000), порівняно 32 (4 — помилка AQL, 4 — порожньо у вікні 5 діб). A = збережений промпт, B = ті самі події через `evidence_agg`, A прогнано двічі для шуму.
- Шум моделі: рішення A1/A2 збігається 32/32 (сер. |Δscore| 0.02). A проти B: 29/32 (|Δscore| 0.09); 2 випадки «закривав → лишити», 1 «лишав → закрити».
- File Decode / Mailto Ransomware (A бачив ≈500 символів): B підозріліший (0.4→0.7, 0.4→0.7, 0.4→0.6). Перевірка сирих подій: 2189258 — `ksolaunch.exe` (WPS Office з AppData\Local) + Zoom registry + тригер правила, тобто 0.7 схоже на хибне спрацювання (виклик людини); 2188479 — 18 FileCreate від powershell + тригер, двозначно.
- Firewall-denies (8 випадків): рішення те саме в усіх, вердикти зсунулись лише у двох.
- Thread Injection порівнювати не можна: B тягне лише лінзу основного правила, A у складених офенсах бачив і рядки інших лінз.
- Збіг із мітками Claude (слабкий орієнтир): A 23/27, B 22/27.
**Висновок (уточнено):** A/B не довів користі від повніших доказів для рішення локальної моделі (3B): на File Decode / Mailto вона реагує сильніше, одна з реакцій схожа на хибну. Але тест НЕ перевіряв скорочення інструкцій: на найгірше обрізаних лінзах (Firewall Denies Between, compromised-host login) B усе одно впирався в 500 символів, тож додаткового місця модель не отримала. Прапорець лишається вимкненим.

## Агрегований блок для датасету (2026-11-20, погоджено)
- `ai_unique.evidence_z` (BLOB, zlib): `evidence_agg.render(сирі події, ai_dataset_evidence_chars=8000)` при першому записі унікального випадку; старі випадки догоняються при наступній появі (`COALESCE`). Збій → NULL, запис не ламається.
- `example_prompt_z` лишається рівно тим, що бачила модель tier-1 (≈500 символів подій). Формат тренувального прикладу обирається при складанні датасету, а не при зборі.
- Ключ `ai_dataset_evidence_chars` (config_schema, 8000).
