# 2026-11-19 — постійне блокування IP з бота (wan-block + опис)

**Що:** у netdiag-боті (група noc@, дії на pa-vm) — «Заблокувати IP»: публічний IPv4 + обов'язковий опис →
тег `wan-block` **назавжди** (User-ID register без timeout, `persistent="1"` — тримається до ручного зняття,
переживає ребут PA). Текстом: `блок 1.2.3.4 причина`.

**Чому не адрес-об'єкт:** ключ бота — user-id (config/commit йому закриті); об'єкт `bot-ip-…` з описом вимагав би
окремого admin-ключа й commit. Обрано варіант із постійним тегом (рішення 19.11).

**Ім'я й опис:** на PA їх немає (registered-ip безіменний). Бот веде реєстр у `netdiag.db`, таблиця `pa_blocks`
(ip, ts, user, description, active); «ім'я» `bot-ip-<IP>` — мітка в боті/сповіщеннях/журналі.
Кнопка «Заблоковані ботом» — список з описами й кнопкою «Зняти» (через картку підтвердження).

**Запобіжники:** лише публічні IPv4; захищені адреси `netdiag_pa_block_protect` (наш периметр:
188.163.216.99, 212.1.103.134, 185.59.227.216/29) блокувати не можна; опис ≥3 символів, ≤120, без `<>`/керуючих;
кожна дія — `pa_actions` + рядок у журналі + вебхук-сповіщення (`netdiag_pa_notify_webhook`). Зняття — існуючий
«розблокуй» (унікально знімає тег і гасить запис у `pa_blocks`).

**Обмеження:** IP, заблоковані не з бота (QRadar, helpdesk-форма), у списку бота не видні; опис живе лише в базі бота.
Тег лише на pa-vm (pa440 — рішення 07.08).

**Файли (repo qradar-ai-middleware):** `netdiag_pa.py`, `netdiag_ui.py`, `netdiag_bot.py`, `config_schema.py`,
`tests/test_netdiag_pa_block.py`. **Відкат:** попередній коміт; таблиця `pa_blocks` безпечно лишається.
