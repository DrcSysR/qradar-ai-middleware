# 2026-08-27 — Спільний хедер «як читати докази» для всіх юзкейсів

## Контекст
Триаж 26.08.2026 ([File Decode](2026-08-26-file-decode-firstcheck.md)) показав, що модель ставила 0.7–0.75 не через докази, а через формат таблиці: читала імʼя лог-сорсу як роль машини і порожню колонку як «unknown path». Пояснення тоді додали лише в `prompts/ransomware_behavior.md`, хоча ті самі формулювання («on an authentication server», «on critical infrastructure», «from an unknown path») трапляються у вердиктах інших юзкейсів — `LOGSOURCENAME()` віддається під аліасами `Host`, `Hostname`, `LogSource`, `Src_Host` у семи AQL.

## Зміна
`app.py`, `build_prompt()` — блок **HOW TO READ THE EVIDENCE** переїхав у спільний wrapper, який обгортає інструкцію будь-якого юзкейсу, тож правило діє й на майбутні промпти без правок:
1. Колонка з іменем лог-сорсу має форму `<DSM> @ <машина>` (`WindowsAuthServer @ mng170.modern.org`, `LinuxServer @ nginx2`, `Bind @ 172.17.61.157`). Префікс називає **парсер**, не роль хоста; `WindowsAuthServer` стоїть на кожній Windows-машині, включно з робочими станціями. Не робити з префікса висновок «DC / auth server / critical infrastructure» і не піднімати за нього скор.
2. Порожнє поле означає «парсер не змапив», а не «невідомо» чи «підозріло». Sysmon не заповнює Process Path на RegistryEvent, QRadar лишає порожніми username/path/port на багатьох типах подій. Порожній шлях — не user-writable шлях.

`prompts/ransomware_behavior.md` — локальний дубль цього тексту згорнуто до одного речення з посиланням на хедер (лишились лише специфіка юзкейсу).

## Бюджет контексту tier-1
Хедер має дві версії: повна (1015 симв.) для Vertex/Ollama і стисла (451) для llm01 з `ctx 8192` — інакше на найдовших юзкейсах хедер відбирав би бюджет у самих логів.

Заразом прибрано магічну константу `fixed_chars = ... + 3200`: розмір промпту без логів тепер міряється точно порожнім рендером (`overhead = len(render("", header))`). Константа вже дрейфувала — реальний boilerplate 3381/3945 симв. проти зашитих 3200, тобто llm01 отримував трохи більший промпт, ніж рахував код.

## Що видно з заміру (не виправлено)
`prompts/compromised_host_cascade.md` — 14 358 символів інструкції при бюджеті llm01 ≈ 14 336. Інструкція **сама по собі** не влазить у ctx 8192: `max_chars` падає на підлогу 500, llama.cpp віддає 400 і юзкейс завжди йде у fallback на Vertex. Це не регресія цієї правки (так було й до неї), але промпт варто скоротити або відправляти цей юзкейс одразу на tier-2.
