## Що зроблено
- Знімок `ai_dataset.db` (1209 унікальних випадків QRadar + 4 Cortex) → унікальні рядки доказів: ін'єкції (≈280 унікальних пар інжектор/шлях/ціль), маячки, брутфорс, фаєрвол, activity-ланцюжки.
- Рядки ін'єкцій розмічено один раз (таблиця `LK` у `tools/dataset_label.py`), решта шаблонів — правилами по сирих подіях зі збереженого промпту (список подій у промпті обрізаний за бюджетом символів — парситься до останнього цілого рядка). Випадок = найгірший рядок (S > U > B; рядки-тригери правил N не голосують).
- Схема в `claude_label`: `close|benign`, `close|insufficient_data` (U = діапазон 0.4–0.6 рубрики, авто-закриття), `review|suspicious` (лише **гіпотеза**, причина починається з `HYPOTHESIS`). `claude_reason` — рядки за класами + головна причина. `human_label` не чіпали. Запис — `UPDATE … WHERE claude_label IS NULL` під `qmiddleware`.

## Результат (станом на 2026-11-20 05:40: 1475 розмічених випадків; 70 без правила — NULL; 4 Cortex розмічені вручну як insufficient_data; дані додавались нічними проходами 01:06, 03:36, 05:40)
| мітка | випадків |

| close\|benign | 657 |
| close\|insufficient_data | 803 |
| close\|malicious (реальна, але зупинена зовнішня атака, «mitigated» у причині) | 2 |

Якщо U рахувати як review: close ≈660 / review ≈815.
`insufficient_data` велика, бо в збережених доказах значної частини випадків (насамперед «Excessive Firewall Denies…», ≈190) лишились лише події-тригери Custom Rule Engine — самого ланцюжка немає; список подій у промпті обрізаний за бюджетом символів. Рядки, які правила не покривають (форма рядка не відома, `injector` немає в таблиці, не-CRE подія з сирим payload), лишаються **NULL**, а не U.
