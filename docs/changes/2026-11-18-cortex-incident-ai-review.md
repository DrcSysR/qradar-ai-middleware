# 2026-11-18 — Cortex: розбір моделлю інцидентів «на перегляд»

**Що:** новий модуль `cortex_incident_ai.py`. Після автотріажу (`cortex_incident_triage.run_triage`) інциденти, що
лишились відкритими з причиною `needs_review` / `mitigated_but_severity_*`, розбирає Vertex (`cortex_incident_ai_model`,
порожньо = `vertex_deep`). У щоденному звіті 09:30 під кожним таким інцидентом — рядок `🤖 <вердикт>: <підсумок> → <наступний крок>`.

**Межі:**
- Лише рекомендація. Модель нічого не закриває і не змінює в консолі; закриття — вручну (як #320).
- Пропускаються assigned / starred / з нотатками / без алертів / з обрізаними алертами — їх уже веде людина або даних немає.
- Вхід: поля алертів з `get_incident_extra_data` (ім'я, категорія, дія агента, хост/користувач, процес і командний рядок,
  файл/sha256, MITRE). Дані в промпті позначені як недовірені; вердикт валідується по білому списку
  (`benign|suspicious|malicious|unclear`), інакше відповідь відкидається.
- Кеш: таблиця `cortex_incident_ai` (`incident_id` + `alert_count`) — повторно інцидент розбирається, лише коли в ньому
  додались алерти; кешований вердикт показується у звіті щодня.
- Ліміти: `cortex_incident_ai_max` (10 нових розборів за прогін), `cortex_incident_ai_max_alerts` (8 алертів у промпті).
  Збій Vertex не валить тріаж і звіт (try/except, інцидент без 🤖-рядка).
- Вимкнути: `cortex_incident_ai_enabled=false` у `config.json`.

**Чому Vertex, а не llm01:** локальна модель 3B замала для розбору командних рядків; обсяг малий (кілька інцидентів на добу).
Дані йдуть тим самим каналом і в той самий проєкт GCP, що й офенси QRadar на tier-2.
**MCP не використовується** — інциденти й алерти беруться з Public API тим самим ключем, що й тріаж.
