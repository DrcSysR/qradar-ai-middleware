# 2026-11-19 — Висновок моделі пишеться в Notes кейсу Cortex; у звіті лишається посилання

**Було.** Розбір моделлю (`cortex_incident_ai`) і збіги з офенсами QRadar займали по 2–3 рядки під кожним кейсом «на перегляд» —
звіт став надто довгим для одного повідомлення Chat (HTTP 400, звіти 17–18.11 не дійшли).

**Тепер.** `write_notes()` у `cortex_incident_triage.py` пише висновок (вердикт, що сталось, що перевірити, відкриті офенси QRadar того ж
хоста) у поле Notes кейсу через Cases API `POST /public_api/v1/case/update/{id}`, `update_data.notes` (успіх = 204), ключем адміна
(`cortex_xdr_admin_api_key_*`). Звіт під таким кейсом показує лише посилання і вердикт: `🤖 🟠 підозріло — розбір у Notes кейсу`.
Якщо запис не вдався — у звіті лишається повний текст, як раніше.

- Нотатка починається з маркера `🤖 Авторозбір middleware` і прямо каже «РЕКОМЕНДАЦІЯ моделі, не рішення». Чужі нотатки НЕ перезаписуються
  (Cases API нотатку замінює, а не дописує); кейс із нашою нотаткою не блокує тріаж (`decide` пропускав усі кейси з notes → тепер лише чужі).
- Повторний запис — лише коли змінилась кількість алертів (таблиця `cortex_incident_noted` в `ai_state.db`). У dry-run нічого не пишеться.
- Ключі `cortex_incident_ai_note` (True) і `cortex_incident_ai_note_max` (60 записів за прогін).
- Окремо: `send_to_chat` повторює при HTTP 429 (Retry-After або 5/10/15 с), між частинами звіту пауза 1,5 с — 19.11 частини без пауз ловили 429.

**Відкрите.** Документація Cases API не вказує окрему роль для `notes`; перший запис — на одному кейсі перед повним запуском. Чи
з'являється Notes у консолі в потрібному вигляді — перевіряє людина.
