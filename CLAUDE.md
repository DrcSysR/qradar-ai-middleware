## qradar-ai-middleware

FastAPI app (`app.py`) + standalone poller (`poller.py`) + standalone botnet scan (`botnet_scan.py`). Dependencies are pinned in `requirements.txt` (versions frozen against the mdlwr01 venv, Python 3.11.2; no lock file, no CI): `fastapi`, `uvicorn`, `gunicorn`, `httpx`, `requests`, `pydantic`, `google-auth`, `urllib3`, plus stdlib `sqlite3`/`fcntl`/`ipaddress`. `autoupdate.sh` reinstalls them by itself whenever `requirements.txt` changed in the pulled commit.

**Architecture:**
- `app.py` exposes `POST /universal-analysis` (body: `{offense_id, is_manual}`) and a `GET /` HTML form. Flow: read offense from QRadar REST → match `offense.description` against keys in `prompts.json` → load matching `prompts/<id>.md` (system instruction) and `queries/<id>.aql` (AQL template with `{offense_id}`, `{limit}`, `{time_depth}` placeholders) → run AQL via `/api/ariel/searches`, poll until `COMPLETED` with a deadline (`aql_poll_timeout_seconds`, default 180 s — a search that does not finish is cancelled and the offense is left OPEN as `AQL_ERROR`, never closed), then `DELETE` the search so it does not pile up on QRadar → send events + instruction to the configured AI provider (`ai_provider: ollama|vertex|openai` in `config.json`) → write a note back to the offense, optionally reassign, auto-close if `score <= 0.6` **or** if the model set `mitigated: true` (the latter closes the offense but KEEPS the firewall block).
- **Composite offenses**: one QRadar offense often carries several contributing rules at once. `prompts_loader.get_matched_lenses()` returns every matching `prompts.json` entry ("lens") in priority order; `app.py` takes the prompt/assignee/refset from the first one but runs the AQL of **all** of them (capped by `max_aql_lenses_per_offense`, default 3) and merges the events, tagging each row with a `Lens` key. `close_on_empty` survives on a composite only when **every** matched lens carries the flag — otherwise an empty result means "unknown", not "clean". Without this, a composite whose primary lens is a known FP auto-closed at score 0.0 with the other rules' evidence never reaching a model.
- `poller.py` is run on a cron/timer separate from the FastAPI service. It queries open offenses from the last `LOOKBACK_TIME_MS` (48 hours) with a cap of `MAX_OFFENSES_PER_RUN` (100) per run, filters to rules listed in `prompts.json` — matching the offense description **or** the name of any contributing rule, because QRadar frequently names an offense after the event ("Traffic End") rather than the use case, skips anything already `PROCESSED` in the SQLite state DB or already carrying an "AI Analysis" note, then POSTs to `http://127.0.0.1:5000/universal-analysis`. Uses an `fcntl` lock on `poller.lock` to prevent overlap.
- `falcon_pua_scan.py` is a separate cron/timer job (suggested daily at 08:00) that pulls CrowdStrike Falcon detections from two QIDs (`103750325` = sensor-based ML; `103750326` = EPP/PUP), parses the LEEF payload (`fileName`/`filePath`/`sha256`/`tactic`/`technique`/`resource`/`url`), filters by configurable allowlists (`falcon_pua_fp_path_regex` for paths like WinSxS / SoftwareDistribution / `AppData\Local\1C\1cv8\` / Arduino15 / IPSPI F3I; `falcon_pua_fp_filenames` for `VisualAssistExe.exe` / `RegsvrPower.exe` / `Template.bin` / `perfnet.dll`; `falcon_pua_fp_sha256` for individual hashes), deduplicates within the run by `(sha256, hostname, filepath)` and against the `falcon_pua_reported` state table over `falcon_pua_dedup_days` (default 30), then POSTs a Markdown report to `falcon_pua_webhook_url` (Google Chat space). The report groups items by workstation and includes filename, full path, SHA256, tactic/technique, and a clickable Falcon Console URL per detection. Sends NOTHING when all Falcon events resolve to known FPs or were already reported. State table `falcon_pua_reported` lives in `ai_state.db`; lock `falcon_pua_scan.lock`; log `falcon_pua_scan.log`. The webhook URL is a secret — keep it in `config.json` (gitignored), never in the script. Defaults live in the script `DEFAULTS` dict; override any key in `config.json`.
- `cortex_xdr_scan.py` is a separate cron/timer job (suggested daily) that pulls Palo Alto Cortex XDR alerts from QRadar and posts a digest to Google Chat — same shape as `falcon_pua_scan.py` but for CEF. It queries `FROM events WHERE LOGSOURCENAME(logsourceid) ILIKE '%Cortex XDR%'` (by log-source name, NOT QID — so it catches alerts even before they're mapped to a QID; the filter substring is configurable via `cortex_xdr_logsource_filter`), parses the CEF header + extension with a space-tolerant parser (`parse_cef` handles values with spaces/commas, escaped pipes `\|` and backslashes `\\`), and extracts `name` (alert), `sig_id` (module: XDR Agent/Analytics/BIOC), `shost`/`suser`, `fileHash`/`initiatorSha256`, `act` (Detected vs Prevented), `externalId`, and the `request` Cortex Console URL. Filters: drops alerts whose CEF severity is below `cortex_xdr_min_severity` (CEF scale 0=Info/3=Low/6=Med/9=High/10=Crit; default 3 = everything except Informational; unknown severity fails OPEN = kept), plus name allowlist `cortex_xdr_fp_alert_names` (default `["Example Cortex XDR Alert"]` — Palo Alto's built-in test event) and `cortex_xdr_fp_external_ids`. Dedupes within-run and against the `cortex_xdr_reported` state table over `cortex_xdr_dedup_days` (default 30) keyed on the alert `externalId` (falls back to `sha256|hostname|alert_name` if externalId is missing). Report groups by workstation and includes alert name, module, severity label, action taken, initiating process, SHA256, a recommended-action line, and a clickable Cortex Console link. Sends NOTHING when there are no new non-Informational alerts. Webhook resolves `cortex_xdr_webhook_url` first, else falls back to the shared `falcon_pua_webhook_url` (current deploy reuses the Falcon Chat space). State table `cortex_xdr_reported` in `ai_state.db`; lock `cortex_xdr_scan.lock`; log `cortex_xdr_scan.log`. Defaults in the script `DEFAULTS` dict; override any `cortex_xdr_*` key in `config.json`. NOTE: Cortex events reach QRadar via the syslog-ng relay on `api-gw` (172.17.61.183) — see the `CortexXDRCustom_ext`/`cortexxdr` log-source onboarding; the scanner is agnostic to that, it only reads what landed in QRadar.
- `botnet_scan.py` is a separate cron/timer job (suggested every 4h) that maintains `ME-PA-Suspicious-IP-Addresses`. Two phases per run: (1) REVIEW — for each IP currently in the set, if QRadar's `last_seen` for the entry is older than `botnet_scan_review_stale_hours` (default 48h), DELETE it (the radar's escalating ban has done its job and the IP went quiet); (2) HUNT — single AQL aggregation over the last `botnet_scan_lookback_days` (default 7) by sourceip, looking for the slow-rotation botnet signature (`Failed≥5 ∧ Failed≤30 ∧ Succeeded=0 ∧ Unique_Users≥2`) — IPs that wouldn't trip any rule's per-IP threshold but match the pattern. Survivors are added to the suspicious set without TTL (radar handles TTL via its escalating PA action on subsequent hits). Excludes IPs already in the set, IPs in any internal asset refset (`Web/SSH/Mail/Windows/...`), and RFC1918. Uses an `fcntl` lock on `botnet_scan.lock`. State written to a separate `botnet_scan` table in `ai_state.db`. Log file: `botnet_scan.log`.
- State lives in **`ai_state.db`** (SQLite, single `offenses` table). `is_manual=true` from the web UI bypasses the "already processed" check; `is_manual=false` from the poller honours it.
- `prompts.json` schema (Ukrainian doc inline): each key is a substring of `offense.description` (or of a contributing rule name); value is `[prompt_filename, assignee_login, aql_filename, refset_cleanup_on_fp?, close_on_empty?]`. The 5th element, when set to the literal `close_on_empty` (or `true`/`1`/`yes`), makes an empty AQL result auto-close the offense as benign at score 0.0 instead of skipping it — for monitoring use cases whose AQL does the benign filtering itself. The 4th element is optional — when set to a reference-set name, the middleware will DELETE the offense's source IP from that set whenever the AI verdict is FP (score ≤ 0.6). Only fires for offenses whose entity is `SourceIP`/`DestinationIP`. Used to roll back QRadar's own auto-add-to-blocklist actions when AI judges the rule fired on a benign IP. There is a special `Default` entry. **Both `app.py` and `poller.py` read this file**, so adding a new use case = add a key + drop the matching `.md` and `.aql`. No code change required.
- `config.json` flag `botnet_dry_run: true` causes BOTH the per-offense FP cleanup (`app.py`) AND the periodic scan (`botnet_scan.py`) to log "would DELETE/ADD X from/to set Y" instead of issuing real API calls. Use this on first deploy to verify the AI verdicts and scan thresholds before letting it touch production block-lists. `botnet_scan.py` reads its tunables from `config.json` keys prefixed `botnet_scan_*` (lookback_days, max_adds_per_run, review_stale_hours, min_failed, max_failed, min_unique_users, min_time_span_seconds, internal_refsets, aql_timeout_seconds) — defaults live in the script.
- Model selection: `is_manual=true` uses `deep_model`/`vertex_deep`, auto runs use `fast_model`/`vertex_fast`. The AQL window is anchored to the **offense's own start/end** (`START offense_start - window STOP offense_end + 5min`), not to `now`; the lead-in is `manual_window_hours` (default 24) / `auto_window_hours` (default 4). Do not raise the manual window casually — a 168 h lead-in on a busy log source (`WindowsAuthServer`, `PaSeries`) turns `INOFFENSE` into a tens-of-GB Ariel scan that never finishes.
- **Cascade triage**: when `escalate_enabled` is set, a tier-1 verdict above `escalate_threshold` (0.6) is re-run on `escalate_provider`/`escalate_model` (Vertex `gemini-3.1-flash-lite`) with a wider `escalate_window_hours` (168) window, and the prompt is rebuilt for the tier-2 provider's context budget. Production runs tier-1 on the on-prem llm01 (`openai` provider, llama.cpp `/v1`, ctx 8192) and escalates to Vertex. Ollama prompts get a `/no_think\n` prefix unless the model is in `MODELS_WITH_JSON_FORMAT` (those use Ollama's `format: "json"` instead).

**Local dev:**
```bash
cd qradar-ai-middleware
# Requires /opt/qradar-middleware/config.json and prompts.json. For local dev,
# either symlink the repo to /opt/qradar-middleware or override the constants
# at the top of app.py / poller.py.
uvicorn app:app --reload --port 5000
python poller.py   # one-shot; designed to be invoked by cron/systemd timer
```

**Tests:** `python3 tests/smoke_test.py` — stdlib only, no QRadar needed. It catches the failure modes that are silent in production: a typo'd `.md` in `prompts.json` (use case silently falls back to the generic prompt), a missing `.aql`, an unknown placeholder in an `.aql`, a `config.json` key absent from `config_schema.SCHEMA`, and a syntax error in any module. Run it before every commit — `autoupdate.sh` uses it as a deploy gate and rolls back if it fails. There is no linter and no CI — don't invent one without asking.

**Docs:** `docs/` follows the department convention — `docs/state.md` is the living description of the current state, `docs/changes/YYYY-MM-DD-<slug>.md` is one immutable record per completed change or audit, `docs/README.md` is the index. A finished change includes its `docs/` entry, in the same commit.

**Deploy:** push to `origin/main`. `autoupdate.sh` runs on the prod host (cron, minutes 9/19/29/39/49/59), detects the new commit, `git pull`s, reinstalls changed requirements, runs the smoke test as a gate, `systemctl restart qradar-middleware`, checks health and rolls back on failure. `./deploy.sh` does the same immediately.
